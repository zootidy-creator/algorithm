# C 语言易错点清单

> **用法**：每踩一个新坑就往里加一条。**期末复习、面试前、蓝桥杯前只翻这一个文件。**
> 格式：**坑 → 正确写法 → 出自哪道题**。带 ⭐ 的是你已经亲手踩过的。
> 最近更新：2026-10-18

---

## 一、字符 vs 数字

### ⭐1. `'0'` 是 48，`0` 才是零
```c
int v = arr[i] - '0';           /* ✅ 字符变数字 */
int v = (i < len) ? arr[i] - '0' : 0;    /* ✅ 补齐的地方要写 0，不是 '0' */
```
- 做高精度加法/数位和时，一旦有 `'0'` 混进算术式，结果会整体偏 48。
- ✅ `arr[i] - '0'` 这个写法的唯一意义就是**减掉那个 48**。
- 出处：`zuoye\1046.c`（高精度加法，等长输入时对、不等长时错）

### 2. `char` 可能是有符号的
- `char` 在 x86 上默认 signed，范围 −128~127；`'z'`(122) 没问题，但 UTF-8 中文会变负数。
- 存二进制/无符号字节用 `unsigned char`。

## 二、运算符

### ⭐3. `=` 是赋值，`==` 才是判断
```c
g->dir = DIR_DOWN;      /* ✅ 赋值 */
g->dir != DIR_DOWN;     /* ❌ 只算了个真假，结果丢掉，什么都没改 */
```
- 光秃秃一句 `x == y;` 或 `x != y;` **什么也不做**，`-Wall` 会报 `statement with no effect`。
- 出处：贪吃蛇 `HandleInput`（三个方向都写成 `!=`，按键没反应）

### ⭐4. 逗号运算符会"吃掉"左边
```c
while (A, B)            /* ❌ 条件其实是 B，A 的结果被丢弃 */
while (A && B)          /* ✅ 两个条件都要用 */
```
- `(A, B)` 的值 = B；**只有 `for` 里的 `i++, j--` 才是它的正当用途**。
- 出处：`zuoye\1078.c`（`while(fgets(...)!=NULL, translation[0]=secret[0])` → 死循环）

### ⭐5. 负数取模，C 的 `%` 跟数学不一样
```c
-27 % 96  ==  -27               /* ❌ C 的结果是负的 */
d = (d % 96 + 96) % 96;         /* ✅ 落在 0..95 */
```
- `if (d < 0) d += 96;` 只在 `d > -96` 时成立，靠题目条件保底。
- 出处：`zuoye\1078.c`

### 6. 整数除法会截断
```c
7 / 2  ==  3                    /* 不是 3.5 */
向上取整(a/b) = (a + b - 1) / b /* ✅ 全整数运算 */
```
- 浮点别写 `1/2`（等于 0），要写 `1.0/2` 或 `0.5`。
- 出处：P5707 上学迟到（WA 三次）、P5713、B2029

## 三、数组与字符串

### ⭐7. 有效下标是 `0 .. len-1`
```c
for (int i = 0; i < len; i++)   /* ✅ */
for (int i = 1; i <= len; i++)  /* ❌ body[len] 越界（垃圾数据） */
```
- 越界读**不一定马上崩**——数组开得大就只是读到脏数据，等变量后面才炸。这类 bug 最难查。
- 出处：贪吃蛇 `CellAt`（`i <= g->len`）

### ⭐8. 字符串必须以 `'\0'` 结尾(重要)
```c
p[len] = '\0';                  /* ✅ 手工拼出来的字符串，最后一行必须是它 */
```
- `printf("%s")` / `strlen` 内部就是"一个字节一个字节找 0"，**它不知道数组多大**。
- 局部数组不初始化 = 栈上残留垃圾 → 打印乱码、输出长度随机、甚至崩溃。
- `= {0}` 只是"碰巧兜住"，不能依赖。
- 出处：`zuoye\1078.c`

### ⭐9. `fgets` 会把行尾的 `'\n'` 读进来
```c
int len = (int)strlen(s);
while (len > 0 && (s[len-1] == '\n' || s[len-1] == '\r'))
    s[--len] = '\0';            /* ✅ 剥掉换行，顺便补上结尾符 */
```
- `while` 而不是 `if`：Windows 是 `\r\n` 两个字符。
- 出处：`zuoye\1078.c`（多算一位）

### 10. `fgets` vs `scanf("%s")`

| | `fgets` | `scanf("%s")` |
|---|---|---|
| 遇到空格 | 继续读 | **停止** |
| 换行符 | **存进缓冲区** | 留在输入流 |
| 长度安全 | 有 `size` 参数 | **无上限，可能溢出** |

- 输入**可能含空格**的整行 → 必须 `fgets`（如 `1078` 密文里可能有空格）。
- 输入是**单个词**（洛谷绝大多数题）→ `scanf("%s")` 更省事，不用剥 `\n`。

### ⭐11. 数组开"上限 + 4"，别开"刚好"
```c
char b[10005];                  /* 题目上限 10000 → 10000 + '\0' + 余量 */
```
- 出处：`1078`（开 10001 零余量）、`1046`（开 90）

### ⭐12. 变长数组 `int a[n]` 是 C99 特性
- 洛谷的 gcc 支持；但 **C11 里它是可选项，MSVC（VS 的编译器）根本不支持**。
- 稳的写法：`#define MAXN 100005` + `int a[MAXN];`
- 出处：`luogu\P5718.c`

### 13. `strlen` 返回的是无符号数
```c
for (int i = strlen(s) - 1; i >= 0; i--)   /* ❌ 空串时 strlen-1 变成巨大无符号数 */
int n = (int)strlen(s);                     /* ✅ 先转 int */
```

## 四、函数与作用域

### ⭐14. 局部变量出不了函数
```c
void f(void) { int x = 1; }     /* x 在 f 返回时就没了 */
```
- 想"把值传出去"：用**返回值**，或者**通过指针参数写回**。全局变量不是答案。
- 出处：贪吃蛇 `MoveSnack` 里的 `oldTail`（`Step` 里拿不到它）

### 15. 传值 vs 传地址
```c
void swapBad(int a, int b);     /* ❌ 交换的是副本 */
void swapOk(int *a, int *b);    /* ✅ 传地址才能真正改掉外面 */
```
- `scanf("%d", &n)` 要 `&` 就是同一个道理：**要让函数改你的变量，必须给它地址**。

### 16. 数组当参数会退化成指针
- `void f(int a[10])` 里 `sizeof(a)` 是 **4 或 8**（指针大小），不是 40。
- 所以**长度必须另外传**：`void f(int a[], int len)`。你早就改对过这一点。

## 五、循环与边界

### ⭐17. 循环条件必须是"能自己变成假"的量
```c
for (int i = 0; i < len; i++)            /* ✅ 规模决定 */
while (fgets(buf, size, stdin) != NULL)  /* ✅ 读到 EOF 就停 */
while (A, B)                             /* ❌ B 永远为真 → 死循环 */
用while的时候一定要检查数组长度            /*要注意循环里面i++会多加一次的问题*/
```
- **读输入只做一次**，别在循环条件里反复读。

### ⭐18. `break` 只跳一层循环
```c
for (...) { for (...) { break; } }       /* 只跳出内层 */
```
- 出处：P1085 不高兴的津津

### ⭐19. 边界要测"刚好相等"那一档

| 类型 | 例子 | 教训 |
|---|---|---|
| 刚好等于 | `1 1 2`（a+b == c） | `>` 和 `>=` 差一个字符，结果完全不同 |
| 特值 | `t == 0`（P5709 苹果和虫子） | 除零要先判断 |
| 长度不对称 | `99 + 1`、`1 + 999` | 高精度/补齐逻辑只在不等长时暴露（1046） |
| 全相等 | `1 1 1` | 等边/等腰同时成立 |

### ⭐20. 自测必须造"不对称"数据
- 只用等长、正常的输入测，`1046` 的 `'0'` 和 `1078` 的多一位都发现不了。
- 每题至少 4 组：**最小的 + 刚好临界的 + 长度/数值不对称的 + 普通的**。

## 六、数学与类型

### 21. 三角形成立要三条不等式
```c
if (a + b > c && a + c > b && b + c > a)   /* ✅ */
if (fabs(a - b) < c)                       /* ❌ 只查了其中两条 */
```
- 三角形分类题（P5717）WA 的根源；**排序后只需查 `a + b > c` 一条**。

### 22. 浮点数不能用 `==` 比较
```c
if (fabs(x - y) < 1e-6)         /* ✅ */
if (x == y)                     /* ❌ 0.1+0.2 != 0.3 */
```

### 23. 注意整型溢出
- `int` 上限约 21 亿；`a*a` 当 `a = 100000` 时是 1e10，**已经溢出**。
- 看到"乘积""阶乘""大数"先想 `long long`（`%lld`）。

### 24. `sqrt` / `pow` 返回 double
```c
int r = (int)sqrt(n);           /* 要取整记得强转 */
if (fmod(b, 1.0) == 0.0)        /* 判断整除用 fmod，不是 % */
```

## 七、输入输出

### 25. `scanf` 的 `&` 和格式符
| 类型 | 格式符 | 要 `&` 吗 |
|---|---|---|
| `int` | `%d` | ✅ |
| `double` | **`%lf`** | ✅ |
| `long long` | `%lld` | ✅ |
| `char` | `%c` | ✅ |
| 字符串 `char s[]` | `%s` | ❌（数组名本身就是地址） |

### 26. `scanf` 不跳过空格的地方
- `%c` **会读到空格/换行**；前面有 `scanf("%d")` 时常常要先 `getchar()` 吃掉换行。
- 一行里有空格分隔的多个数 → `scanf("%d %d")` 没问题。

## 八、脚本与工具链（不是 C，但能让你卡半小时）

### ⭐27. `.bat` 是纯 ASCII 文件，`rem` 注释里不能有中文和 `& | < >`
```bat
rem  错误：消息里不要出现 & | > < 这些符号
rem  ↑ cmd 的 rem 并不保护特殊字符：& 会断句、> < 变成重定向、中文按 GBK 读成乱码
rem  ↑ 结果：注释被拆成几条"命令"去执行 → 屏幕上 'xxx' 不是内部或外部命令
rem  正确：rem 后面只写英文，bat 里永远不出现中文和 & | < > ( )
```
- **第二个后果**（更阴）：这些垃圾命令会打乱后面的 `if errorlevel (...)` 块，导致 `git commit` 被静默跳过 —— 现象是"明明改了文件，却显示 nothing to commit"。
- 口诀：**`.bat` 全 ASCII 不用特殊符号；`.ps1` 存 UTF-8 with BOM，打印内容也用英文。**

### ⭐28. `.ps1` 必须存成 UTF-8 **with BOM**
- 没有 BOM 时，Windows PowerShell 5.1 按 GBK 读 → 中文乱码 → 报 `字符串缺少终止符`。
- 每次改完 `.ps1` 都要确认 BOM 还在（VS Code 右下角看编码，或另存为时选 "UTF-8 with BOM"）。

### 29. `git` 的 CRLF 警告不是错误
```
warning: in the working copy of 'x.c', LF will be replaced by CRLF the next time Git touches it
```
- Windows 上 Git 自动处理换行符，看到可以无视。

## 九、每次提交前的 30 秒自查

- [ ] 编译 **0 warning**（`-Wall -Wextra`）——警告不是噪音
- [ ] 数组下标上界是 `len-1`
- [ ] 每个 `char` 数组手工拼完都补了 `'\0'`
- [ ] 用了 `fgets` 就剥了 `\n`
- [ ] `=` / `==` 没写反
- [ ] 边界的 4 组数据都跑过（最小 / 临界 / 不对称 / 普通）
- [ ] 输出格式（换行、空格、精度）和样例逐字符对过
