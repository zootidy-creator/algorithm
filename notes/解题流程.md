# 解题流程（每次做题照做）

> 用法：做题时把这个文件摊在旁边，**按顺序照做，不许跳步**。
> 目标：把"我知道但手滑"变成历史，21 天成肌肉记忆。
> 起点：2026-10-18

---

## 一、解题五步法（写在纸上或注释里）

### 第 1 步：抄样例，手算一遍
- 把题目的输入 → 输出**抄下来**
- 自己**手算**一遍，把每步变量值写在纸上（这题就是靠这一条发现结构问题的）
- 至少凑 4 组：**最小 / 刚好临界 / 不对称 / 普通**

### 第 2 步：用人话写算法（3-5 行，不许出现 C 语法）
```
例（1050 找子串）：
  让起点 i 从 0 走到「最后一个还能放下 b 的位置」
    从这个位置开始，逐个字符和 b 比
    全都对上了 → 输出 i+1，结束
```
**模糊的想法必然变成模糊的代码。** 如果这段话里"走到哪里"说不清，代码里就会有 `i < lenb` 这种错。

### 第 3 步：定变量表（每个变量一行）

| 变量 | 含义 | 范围 | 谁负责维护 |
|---|---|---|---|
| `i` | a 里的起点位置 | 0 ~ lena-lenb | 外层 `for` |
| `j` | b 里的位置 | 0 ~ lenb-1 | 内层 `while` |
| `lena` / `lenb` | 两个串的长度 | — | 开头算一次，别重复调 `strlen` |

**关键检查**：两个变量的单位必须一致才允许比较。`i`（a 的位置）和 `lenb`（b 的长度）**不该出现在同一个条件里** —— 1050 就错在这。

### 第 4 步：小步翻译，10-15 行编译一次
- 先写"读入 + 输出样例里的常量"，跑通
- 再写核心循环，跑一组
- **绝不允许一口气写 60 行再编译**

### 第 5 步：自测 4 组数据，全过才提交
```
最小：      1 1
临界：      1 1 2        ← 刚好相等的那一档
不对称：    XAAB / AB    ← 首字符出现但整体不匹配
普通：      样例 + 1 组自己想的
```
**你三次翻车（1046、1050、1078）全是"不对称数据"才暴露的。**

---

## 二、五个固定动作（每题都做，共 2 分钟）

1. **写 10-15 行就编译一次** —— 每次只面对 1 个错误，而不是 5 个
2. **每个循环先写注释：起点 / 终点 / 每次怎么变**
   ```c
   /* i: 0 → lena-lenb ; j: 0 → lenb-1 */
   ```
3. **每个下标表达式问一句："这个变量代表什么？"**
4. **编译警告必须清零**（`-Wall -Wextra`；警告都是真线索）
5. **提交前跑完第 5 步的 4 组数据**

---

## 三、卡住时的处理顺序

1. 自己再想 5 分钟（**不许**立刻搜题解）
2. 加一句打桩：`printf("i=%d j=%d a[i]=%c\n", i, j, a[i]);` —— 看它到底走到哪一步
3. 还卡 → 看题解 → **关掉页面从零重写**
4. **隔 2 天再默写一遍**（只看不重写 = 没看）

---

## 四、每次犯错后必做（10 秒）

在 `notes\C易错点.md` 里加一行：

```
⭐N. 坑 → 正确写法 → 出自哪道题
```

**21 次之后你就有一份别人没有的个人知识库。** 期末、面试、蓝桥杯前只翻它。
